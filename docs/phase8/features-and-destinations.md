# Phase 8 homepage helpers, destinations, and Panic appearance

Baseline: merged main `2725f32` after #202. Budsin Games, the separate Monochrome shortcut, Save Heavenly, and a local document appearance were absent. Arctic already existed as `bm_arctic` with a folder of mirrors; it was extended in place rather than renamed or duplicated. Existing panic controls provided a saved website redirect and a touch button, without an appearance selector in this checkout.

## Implemented

- Canonical catalog `2026.10.27.1` adds `bm_budsin_games` to Games and the exact MyOxyPages/HTMLPut URLs as `sub_arctic_myoxy` and `sub_arctic_htmlput` under `bm_arctic`. The existing review/apply mechanism preserves saved preferred/active links, personal notes, mirror order, hidden states and personal bookmark placement. No migration silently resets an existing collection.
- A 42px music-note button beside the homepage actions opens an accessible native dialog linking to `https://monochrome.tf/`. Exact tip: “If the music doesn't play, try downloading it instead”. No media element, autoplay or automatic tab opening. **Show Music Shortcut** in searchable Settings persists as `showMusicShortcut`, defaults on, and responds to other-tab settings changes. This is independent of rotating music-note eligibility.
- **Save Heavenly** lives inside the existing About disclosure. It offers desktop Ctrl+D/⌘D instructions and a native draggable, clean homepage anchor; touch browsers get their bookmark menu instructions. It explains that websites cannot add browser bookmarks automatically and that bookmarking does not back up local data. Browser-chrome drop acceptance cannot be established by page automation.
- **Panic Button appearance** adds **Document workspace** beside the preserved default **Open saved website**. Both existing panic-key and touch-button paths use the selected destination. The saved panic URL survives selecting document mode. The local document is reserved before proxy Referer recovery, so opening it from an actual proxy page stays on Heavenly's own route.
- `/study-workspace.html` is an original, lightweight document-style page: title, page, academic watershed notes, editable content and basic Bold/Italic/Underline, paragraphs/headings, list, Undo/Redo controls. It has no third-party frame, sign-in UI or account claim. **Return to Heavenly** restores the same-origin page captured before opening; fallback is `/`. Return URLs reject cross-origin and protocol-relative inputs. Paste accepts text only; HTML drops are refused. Edits remain only in the current open tab and the footer says so.
- Adapted compatible Palette PR #205/#206 keyboard navigation: cloak preset options respond to ArrowUp/Down/Home/End, with wrapped traversal across the actual listbox options. No independent PR was merged.

## Validation

`npx mocha test/unblocker-client.test.js test/phase8_features.test.js test/catalog_updates.test.js test/launch_preference.test.js --reporter dot`: **66 passing**. This includes an actual merged-main catalog loaded in a VM, then review/apply into customized saved data, proving preferred mirrors, notes, order and a personal bookmark survive the new release.

`PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1 node test/browser/phase8_features.cjs` exercises real rendered controls in Chromium, Firefox and Linux WebKit. It covers the exact music tip/link, Escape/focus return, Save instructions, clean drag anchor, actual settings visibility and reload persistence, Palette keyboard navigation, the actual injected panic key and touch button, editable formatting, and unchanged saved-website panic behavior. It measures the workspace at 1440×1000, 1366×768, 820×1180, 1180×820, 390×844, and 320×740. Final result: **7 groups in each of Chromium 154, Firefox 153 and Linux WebKit 26.5, all passing with zero page errors; six measured workspace sizes per engine**. Detailed actual results are in `evidence/features-results.json`; genuine Chromium screenshots include `music-shortcut-desktop.png`, `save-heavenly-desktop.png` and `document-workspace-{1440,820,320}.png`.

The first cross-browser run exposed a real local-route integration bug, fixed by reserving the workspace before proxy Referer recovery. A subsequent Firefox test reached the configured homepage URL and DOMContentLoaded but timed out waiting for all external resources; the test now waits for the application document and its existing readiness signal, rather than unrelated remote icon/font network completion.

`evidence/external-links.json` records bounded HEAD requests, following at most four redirects with a 20-second limit. Budsin and both exact mirrors returned **HTTP 200**. Monochrome returned **HTTP 503** in this environment; the requested link is retained, and playback/service availability remains unverified. No third-party page scripts were executed.

No physical iPad, Chromebook, phone, Apple Safari, native bookmark-bar drop, browser menu, hardware keyboard, or virtual keyboard was tested. Linux WebKit is browser automation, not Apple Safari. Basic rich-text formatting uses the browser's native editing commands; no editor library was introduced. The document is intentionally not a cloud storage or permanent drafting feature.
